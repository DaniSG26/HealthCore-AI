# ☕ Instructions for AI Agents Operating in HealthCore

**Purpose:** This file is the first thing an AI agent should read before making ANY changes to this repository.

---

## 🎯 Before You Do Anything

An AI agent operating in this monorepo must read these documents **in this order**:

### 1️⃣ **Business Context (THE WHAT & WHY)**
📄 **File:** [`CONTEXT.md`](./CONTEXT.md) or [`CONTEXT.es.md`](./CONTEXT.es.md)

**Learn:**
- What is HealthCore (12 clinics, 2 countries, 200 people)
- What problems we're solving
- Which departments exist and what they need
- Why this code matters (patient safety, compliance, real people)

**Time needed:** 10-15 minutes

---

### 2️⃣ **Technical Context (HOW WE BUILD)**
📄 **File:** [`docs/TECHNICAL_CONTEXT.md`](./docs/TECHNICAL_CONTEXT.md)

**Learn:**
- Technology stack (backend, frontend, data, AI)
- Code naming conventions (Python: snake_case, TypeScript: camelCase)
- Folder structure and where things go
- Data sensitivity and compliance requirements
- Decisions that are still TBD

**Time needed:** 10 minutes

---

### 3️⃣ **Agent Operations Workflow (THE PROCESS)**
📄 **File:** [`AGENTS.md`](./AGENTS.md)

**Learn:**
- The mandatory workflow BEFORE any commit
- What PRs must include
- Prohibited actions (direct pushes, unexplained changes)
- When to use skills vs. when to code from scratch

**Time needed:** 5 minutes

---

### 4️⃣ **Specific Technical Conventions (THE RULES)**
📁 **Folder:** [`.agents/`](./.agents/)

**Learn:**
- Language-specific conventions (Python, TypeScript, etc.)
- Data handling rules (what's sensitive, what's not)
- Compliance rules (HIPAA, UK GDPR, never break these)
- Folder structure (what goes where, don't innovate)

**Time needed:** 5-10 minutes (read only what applies to your task)

---

### 5️⃣ **Available Skills (REUSABLE CAPABILITIES)**
📁 **Folder:** [`skills/`](./skills/)

**Learn:**
- What pre-made capabilities exist
- When to use a skill vs. writing custom code
- How to combine skills for complex tasks

**Time needed:** 2-5 minutes (skim available skills)

---

## ✅ The Agent Workflow (Before Any Commit)

```
START
  │
  ├─→ Read all 5 documents above? ✓
  │
  ├─→ Create feature branch (don't push to main)
  │
  ├─→ Write code or changes
  │
  ├─→ Check against .agents/ conventions
  │   ├─→ Passes? Go to next step
  │   └─→ Fails? Fix it
  │
  ├─→ Run any required linting/testing (if configured)
  │   ├─→ Passes? Go to next step
  │   └─→ Fails? Fix it
  │
  ├─→ Write clear PR description
  │   ├─→ What changed?
  │   ├─→ Why did you change it?
  │   ├─→ How did you test it?
  │   └─→ Any compliance/security concerns?
  │
  ├─→ Create PR (do NOT merge yourself)
  │
  ├─→ Wait for review (if human review is configured)
  │
  └─→ DONE
```

---

## 🚫 Agent Prohibitions (NEVER DO THIS)

| ❌ Prohibited | ✅ Alternative |
|-------------|----------------|
| Direct push to `main` branch | Create a feature branch, open PR |
| Commit with message "fix" | Explain what changed and why |
| Modify folder structure | Read `.agents/folder-structure.md` first |
| Ignore compliance rules | Read `.agents/compliance-rules.md` |
| Write code without understanding context | Read CONTEXT.md first |
| Copy-paste code from examples without review | Understand why the code works |
| Expose patient data in logs/errors | Use data classification from TECHNICAL_CONTEXT.md |

Agents can use these tools and resources:

- **File operations:** Read, write, search files
- **Terminal commands:** Run build, test, lint commands (if configured)
- **Git operations:** Branch, commit, push to feature branches

## 🆘 If You're Unsure

**Question:** "Can I do X?"

**Process:**
1. Search `.agents/` for relevant rule
2. If found and clear → follow it
3. If not found or unclear → it's probably TBD
4. Leave a comment in your PR explaining your decision
5. Wait for human review

## 🎯 Success Criteria for Agent Work

Your changes are ready when:

- ✅ You read all 5 documents before starting
- ✅ Your code follows the conventions in `.agents/`
- ✅ You didn't break any compliance rules (`.agents/compliance-rules.md`)
- ✅ You didn't innovate the folder structure (`.agents/folder-structure.md`)
- ✅ Your PR has a clear description (what + why + how tested)
- ✅ You created a feature branch (not direct to main)
- ✅ You waited for review (didn't self-merge)
